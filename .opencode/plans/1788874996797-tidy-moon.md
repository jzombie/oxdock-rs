# Plan: Committed Keyword Parsing — `invalid syntax for command X` vs `unknown command`

## Problem
Structural keywords (`WITH_IO, AWAIT, CANCEL, ASYNC, TIMEOUT, FOR, IF, LET, INHERIT_ENV`, plus `ELSE`) are PEG rules in `crates/oxdock-parser/src/dsl.pest:15,19,179-180`. When args are malformed, the PEG choice fails and falls through to generic `instruction_inner` (`command_name ~ args`), then `lower_command` in `crates/oxdock-parser/src/commands.rs:311-331` reports `unknown command: X` with a hint second line (`structural_hint`, `commands.rs:187-224`). Reporting a known keyword as "unknown" is a classification bug. Per user decision: known keyword + bad args MUST emit `invalid syntax for command <X>: <reason>`; only unregistered keywords emit `unknown command`.

User decisions (mandatory):
- Replace, don't prefix: never retain `unknown command` for registered keywords.
- Universal commitment: all keywords in `CommandMeta` registry + structural set commit on lead token (leaf + structural).
- Implementation in Rust two-stage dispatcher (`parser.rs`), NOT Pest cut/lookahead hacks.

## Findings (Phase 1 explore)
- `dsl.pest` has NO per-leaf rules (`sleep_statement` doesn't exist). Leaf commands (`SLEEP`, `RUN`, `COPY`...) already go via generic `instruction_inner` → `lower_instruction_pair` (`parser.rs:596-615`) → `declare_commands!::lower_command` which validates arity/types and already emits specific errors (e.g. `SLEEP requires...`, `SLEEP: argument...`). Only truly unknown names hit `unknown_command_error` (`commands.rs:174-185`).
- The fallthrough bug only affects structural keywords: e.g. `AWAIT ECHO "test"` fails `await_statement`, matches `instruction_inner` with name=`AWAIT`, then hits `unknown_command_error` + `structural_hint`. Tests currently pin this wrong message (`commands.rs:1407-1440`: `WITH_IO [stdout=discard]...`, `AWAIT ECHO...` assert `unknown command`).
- Errors are untyped `anyhow::Error` strings; no Pest-level fallback rule. `lexer.rs:36-74 tokenize`, `format_pest_error:76-140` handle grammar failures. Lowering errors propagate without `line_no` (`parser.rs:104ff, 436-441`).
- `Command::parse` (`ast.rs:37-64`) and `COMMANDS` (`ast.rs`) exist but are only used for diagnostics/quoting, not dispatch. Canonical dispatch is `lower_command(name, args)`; structural metadata via `all_structural_metadata()`.

## Approach (Rust two-stage dispatcher, no `dsl.pest` structural change)
Keep grammar for tokenization; establish commit boundary in Rust before/instead of `unknown_command_error`.

### Step 1 — Keyword registry helper (`commands.rs`, near `unknown_command_error:174`)
- Add `fn is_known_command(name: &str) -> bool`: true if `all_metadata().iter().any(|m| m.name == name)` OR structural keyword set. Explicitly include `"ELSE"` (misplaced `ELSE` outside an `IF` block falls through to `instruction_inner` and must commit) plus `WITH_IO, AWAIT, CANCEL, ASYNC, TIMEOUT, FOR, IF, LET, INHERIT_ENV`. Note: `ELSE IF` is two tokens — the lead token `ELSE` commits; do not add a separate `"ELSE IF"` entry, handle via the `ELSE` branch reason text. Verify whether `all_metadata()` (via `all_structural_metadata`) already covers the set; keep the explicit `ELSE` check regardless since it is not a standalone command but is in `structural_hint`.
- Alternatively expose `Command::parse(name).is_some()` + structural set; prefer single helper to avoid drift. Do NOT add workspace-wide allows; follow guardrails (localized allows only).

### Step 2 — Split error constructors (`commands.rs:174-282`)
- Keep `unknown_command_error(name, raw_args)` ONLY for `!is_known_command(name)` (preserve `case_hint` for `echo`→`ECHO`, bare message for `FROBNICATE`).
- Add `pub(crate) fn invalid_syntax_error(name: &str, raw_args: &[Arg]) -> anyhow::Error` producing `invalid syntax for command {NAME}: {hint-body}`. Reuse existing `structural_hint` bodies + `with_io_hint` diagnostics as the `<reason>`; reword from `WITH_IO needs...` hint to reason clause. For leaf-known names that somehow reach fallback (shouldn't happen), fall back to generic `invalid syntax for command {NAME}: got {got}`. This is the single canonical constructor — all dispatch paths call it, no inline string building elsewhere.
- Behavior matrix:
  - `FROBNICATE hi` → `unknown command: FROBNICATE` (unchanged).
  - `echo hi` → `unknown command: echo` + `did you mean ECHO` (unchanged, lowercase not committed).
  - `AWAIT ECHO "test"` → `invalid syntax for command AWAIT: AWAIT waits for...; got ...` (no `unknown command` substring).
  - `WITH_IO [stdout=discard] ECHO...` → `invalid syntax for command WITH_IO: ... invalid binding ...` (reuse `with_io_hint`).
- Leaf-error prefix standardization (SEV-2 fix, mandatory for universal commitment): update `validate_positionals_against_meta` and `strip_flags` in `crates/oxdock-parser/src/command.rs` / `strip_flags.rs` so EVERY validation error they emit is wrapped as `invalid syntax for command {cmd_name}: <reason>`. Covers e.g. `SLEEP expects at most 1 positional argument(s), got 2` → `invalid syntax for command SLEEP: expects at most ...`, and `unknown flag --foo for command SLEEP` → same prefix. Do this at the point of construction (pass `cmd_name` in) rather than string-matching at the call site, so structural and leaf paths share one error interface.

### Step 3 — Wire commit in dispatch (`commands.rs:311-331` + `parser.rs:596-615` + `parser.rs:436-441`)
- In `lower_command`'s catch-all `_ =>`: branch on `is_known_command(name)` → `invalid_syntax_error` vs `unknown_command_error`.
- In `lower_instruction_pair` (`parser.rs:596`): optionally add explicit guard for structural keywords that delegates DIRECTLY to `commands::invalid_syntax_error` (no local message construction). Do NOT prepend `line {n}:` manually inside `lower_instruction_pair` — error payloads stay clean of inline line prefixes so leaf and structural errors share one shape.
- Line context uniformly at the top-level boundary: if location context is needed, add it once in `parse_script` / `ScriptParser::parse` (`parser.rs:104ff, 436-441`), not in per-branch dispatch. If `parse_script` enrichment is out of scope, leave lowering errors without line numbers (current behavior) rather than adding branch-specific prefixes.
- Do NOT add Pest lookaheads/cuts, do NOT reorder `command` choices, do NOT add `_` param prefixes; obey lint rules (`clippy.toml` denies, no crate-level allows).

### Step 4 — Update pinned tests + add coverage
- Update `commands.rs:1407-1440` (`malformed_with_io_binding_names_the_bad_binding`, `await_without_task_variable_points_at_syntax`) to assert `invalid syntax for command WITH_IO/AWAIT` and assert NOT contains `unknown command`. Keep `genuinely_unknown_command_keeps_bare_message` and `lowercase_command_suggests_uppercase` on `unknown command` path.
- Add cases for each structural keyword misused as instruction: `CANCEL foo`, `TIMEOUT foo`, `FOR ...`, `IF ...`, `LET ...`, `INHERIT_ENV ...`, `ASYNC` bare, `ELSE ...` → all `invalid syntax for command X`.
- Add negative: `FROBNICATE`, `echo` still `unknown command`.
- Check `crates/oxdock-parser/tests/integration/` (`timeout_block.rs:136-148`, `invalid_env_inversion.rs`, `inherit_env.rs`, `with_io_block.rs`) and `crates/oxdock-logic-tests` parity fixtures (`fixtures/parity/invalid_lowercase`) for string asserts needing updates.

### Step 5 — Docs (generated READMEs — do NOT hand-edit)
- If error strings appear in docs/templates, edit sources under `<crate>/.oxdock/template/` + `.oxdock/template/_global/values.json`, then `cargo run -p docs-gen` and commit regenerated outputs (per AGENTS.md).
