## Session-confirmed user traps to document
1. Shell quoting: `echo "{{ $test }}"` (double quotes) lets the shell eat `$test` → stdin becomes `{{ }}` → `invalid placeholder format ''`. Use `echo '{{ $test }}'`.
2. `FOR $x IN GLOB(*)` → "unknown command: FOR... got `$x IN GLOB(*)`". `*` is not a `bare_word`; must quote: `GLOB("*")`. Single-line `FOR ... { ECHO ... }` also parses.
3. `EXPAND FILE=$x` is an override (`KEY=val`), not a path. Path form: `EXPAND {{ $x }}` or `EXPAND $x`. Override-value form: `EXPAND <path> FILE={{ $x }}` (bare `$x` stays literal — only `{{ }}` interpolates outside `RUN`).
4. `EXPAND FILE="testing 1 2 3"` → "EXPAND accepts at most one path". Root cause: `dsl.pest:207-211` — whitespace always separates arguments (atomic `instruction`), `unquoted_arg` stops at space, so the value splits into 4 args (`FILE="testing`, `1`, `2`, `3"`); lowering (`commands.rs:651-665`) treats the first as override and the next two bare words as two paths → bail. Override values with spaces are unexpressible in current grammar.

## Bugfix B (REQUIRED, security: GLOB("../") escapes the sandbox)
- Root cause: `glob_paths` (`crates/sys/oxdock-fs/src/workspace_fs/path.rs:202-234`) prefixes the user pattern onto the escaped root (`{root}/{pattern}`) and filters with lexical `path.starts_with(&self.root)` (`:229`). `starts_with` is component-wise and `..` is an ordinary component, so `<root>/..` and `<root>/../sibling` PASS the check; `evaluate_glob` (`crates/oxdock-core/src/exec/args.rs:180-188`) then `strip_prefix`es them into `".."` / `"../sibling"` — sandbox-relative escapes returned as a plain `List`, usable by `FOR`/`READ`/`EXPAND`/`COPY` (parent-dir listing disclosure at minimum).
- Fix (defense in depth, `oxdock-fs` + `oxdock-core`): after `strip_prefix`, drop (or error on) any result whose relative path contains a `ParentDir` component — i.e. never return a path that lexically escapes the root; optionally also reject `..`-containing patterns up front in `evaluate_glob`. Audit same-class paths: `LOAD_TOML`/`LOAD_JSON` go through `fs.resolve_read` — verify it already rejects `..` escapes and add a regression test proving it.
- Verification: regression tests `GLOB("../")`, `GLOB("../*")`, `GLOB("a/../../*")` return empty (never outside paths); normal `GLOB("*")` still lists sandbox contents; `cargo test -p oxdock-fs -p oxdock-core`; docs note that GLOB patterns are sandbox-root-relative and `..` is filtered.

## Parser unification (REQUIRED code fix, per user: EXPAND FILE=$x must work like ECHO $x)
- Problem: `ECHO $x` works (single `Arg::Expr` preserved through `parse_argument` `parser.rs:1045` → `join_args` len==1 passthrough `commands.rs:28` → `evaluate_expr`), but `EXPAND FILE=$x` flattens fragments to `Arg::String("FILE=$x")` (`parse_fragments` `parser.rs:1065-1096`) and lowering `split_once('=')` (`commands.rs:651-665`) yields value `Arg::String("$x")`, which `expand_string` leaves literal (bare `$` literal by design, `args.rs:284-286`). Same family: `join_args` multi-arg branch joins `a.as_str()` where `Arg::Expr.as_str()==""` (`ast.rs:263`) — drops exprs (e.g. `ECHO $x hello`).
- Fix (in `oxdock-parser`, no behavior change to expansion semantics): preserve `(key, Arg)` structure through lowering instead of flatten-then-resplit — shared override-arg helper that keeps the value as `Arg::Expr` when it is a lone expr (covers `FILE=$x`, `FILE=$d.items`, `FILE=GLOB("*.md")`), plus expr-aware `join_args` so multi-arg commands (`ECHO`/`RUN`/`WRITE`/`APPEND`/`ASSERT_*`) no longer drop `Arg::Expr` via `as_str()==""`. All value resolution then flows through the existing `resolve_arg` → `evaluate_expr`/`expand_string` path uniformly.
- Verification: unit tests in `oxdock-parser` (lowering preserves `Arg::Expr` for `KEY=$var`; `join_args` keeps exprs), exec tests (`EXPAND tmpl FILE=$x` ≡ `FILE={{ $x }}`; `ECHO $x hello` keeps value), regression via `cargo test -p oxdock-parser -p oxdock-core`, then full `cargo test --workspace --tests`.
