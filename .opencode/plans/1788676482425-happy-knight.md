# Plan: Fix ENV quoted values with spaces (e.g. `ENV SET_FORTH="outer scope"`)

## Issue summary
`ENV SET_FORTH="outer scope"` stores `"outer` (leading delimiter kept, ` scope"` dropped) instead of `outer scope`. Every other command (`RUN`, `ECHO`, `WRITE`, `ASSERT_*`) handles quoted strings with spaces via shared `parse_fragments` unquoting + `join_args`; `ENV` is the outlier.

## Root cause (verified from source)
- Grammar `crates/oxdock-parser/src/dsl.pest:191-192,207-211`: generic `instruction = ${ command_name ~ (sep ~ argument)* }` (compound-atomic). `unquoted_arg` allows `"`/`=` as bare chars, so `SET_FORTH="outer scope"` lexes as two `argument`s: `SET_FORTH="outer` + `scope"`.
- `parse_argument`/`parse_fragments` (`crates/oxdock-parser/src/parser.rs:1042-1096`) correctly unquotes single `string_literal` fragments, but the split already happened at `sep` level, so `ENV` never sees a single arg.
- `ENV` lower (`crates/oxdock-parser/src/commands.rs:377-382`) takes only `args[0]`, `split_once('=')`, strips only `"` (not `'`), forces `Arg::String(_, false)`. Test/mock duplicates in `crates/oxdock-parser/src/lib.rs:83-96`, `oxdock-build/src/track.rs:331-344`, `oxdock-build/src/assets.rs:681-694` strip nothing at all.
- `EXPAND` overrides (`commands.rs:651-665`) share the same `split_once` per-arg pattern and likely have the same space bug.
- Exec (`crates/oxdock-core/src/exec/steps.rs:279-282`, `handlers.rs:74-81,1162-1171`, `args.rs:24-32`) just stores `resolve_arg` verbatim — no re-quoting, so fix belongs in lowering.

## Decisions (confirmed by user)
- Parse exactly like every other command (both `"` and `'` stripping via shared path).
- Unquoted multi-word `ENV FOO=outer scope` joins with space (same as `RUN`/`ECHO` `join_args`).
- Fix both `ENV` and `EXPAND` overrides.

## Proposed fix (recommended: minimal, consistent with other commands)
1. **`crates/oxdock-parser/src/commands.rs` — `Env` lower:**
   - Rejoin all positional args with single spaces (reuse existing `join_args(args, "ENV")`, same as `ECHO`/`RUN`/`WRITE`), then `split_once('=')`.
   - Strip both `"` and `'` surrounding quotes (mirror `EXPAND` lower at `commands.rs:657-659` / `unquote` at `parser.rs:1335-1340`), not just `"`.
   - Preserve/normalize `Arg::String(..., false)` as today (or preserve quoted flag if needed for `strip_flags`; `ENV` has no flags so `false` is fine).
   - Result: `ENV SET_FORTH="outer scope"` → join → `SET_FORTH="outer scope"` → split → `v='"outer scope"'` → strip → `outer scope`.
2. **Same fix for `EXPAND` overrides loop** if in scope (joins split override tokens before `split_once`; careful: `EXPAND` also takes an optional path arg, so join logic must only apply to `KEY=...` tokens or re-assemble split pairs).
3. **Unify/remove duplicate `ENV` lowerings** in `crates/oxdock-parser/src/lib.rs` (test helper), `oxdock-build/src/track.rs`, `oxdock-build/src/assets.rs` — or apply identical join+strip there so behavior is pinned everywhere.
4. **Tests:**
   - Parser unit: `ENV SET_FORTH="outer scope"` → `StepKind::Env { key: "SET_FORTH", value: "outer scope" }`; single-quote variant; `=` in value (`ENV A=b=c` → `b=c`); empty/unquoted still work.
   - Core integration (cf. `crates/oxdock-core/tests/integration/unquoted_syntax.rs:157-162`): set + `ECHO $SET_FORTH` / guard `eq(env:SET_FORTH,outer scope)` round-trip; `Display` (`commands.rs:1003` + `quote_arg`) already re-quotes.
   - Fixture: extend `crates/oxdock-logic-tests/fixtures/commands/ast_commands/cases/env/case.toml` or add `env_quoted_spaces` case; run `cargo test --workspace --tests`.
5. **Docs:** update `ENV` `syntax`/`examples` in `commands.rs:367-383` if needed (`ENV KEY="value with spaces"` example).
6. **EXPAND named-vars example (source-of-truth is the command macro, not README):**
   - Current example (`commands.rs:645-650`) only shows `ENV` + `{{ env:NAME }}` interpolation; it never shows `EXPAND [<path>] [<KEY=val> ...]` overrides, so add override coverage, e.g.:
     ```oxdock
     WRITE template.md "Hello {{ env:NAME }}!"
     EXPAND template.md NAME="Alice"
     ASSERT_STDOUT "Hello Alice!"
     ```
     plus a quoted-value-with-spaces override (ties to this fix, e.g. `NAME="Alice Smith"`) to pin the join-then-split behavior.
   - Edit only `crates/oxdock-parser/src/commands.rs` `Expand` `examples`; do NOT hand-edit generated files.
   - Regenerate via docs-gen (`crates/docs-gen/src/main.rs`: writes `docs/sections/07-command-body.md` + `06-command-reference.md`, then assembles root `README.md` from `docs/sections/*.md`); verify `README.md:987-1012` picks up the new example.
   - Verify the new example actually passes (run it as a script / relevant test) so docs never show a non-working override form.

## Alternative considered (not recommended)
- Dedicated pest rule `ENV KEY="quoted value"` at grammar level. Cleaner tokenization but invasive: touches `dsl.pest`, `lexer.rs`, `parser.rs` `extract_instruction`, macro reconstruction (`macro_input.rs:93-124`, `oxdock-macros/src/lib.rs:136-148`), and risks cross-platform/parity regressions. Join-in-lowering achieves identical behavior with a 5-line change following existing `join_args` precedent.
